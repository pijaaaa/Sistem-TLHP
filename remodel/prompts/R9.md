# R9 — Notifikasi, Inbox Persetujuan, Pelacakan, Pengingat

## Konteks
R0–R8 selesai. Service R2–R8 sudah men-dispatch Domain Event (listener no-op). Sekarang notifikasi in-app, pelacakan tugas, dan pengingat otomatis (tanpa email). Baca roadmap bagian 7.

## Tugas
**Backend**
1. Tabel `inbox_tasks`: recipient_id, task_type (enum), subject_type/subject_id (polimorfik: temuan/AP/TL), title, received_at, first_opened_at (nullable), acted_at (nullable), status (`OPEN`,`DONE`), created_by.
2. `TaskDispatcher` + listener untuk semua event, membuat inbox task **dan** notifikasi untuk penerima yang tepat:
   - `ActionPlanSent` → manager_dept (tentukan PIC); `PicAssigned` → PIC; `FollowUpSubmitted` → manager; `FollowUpDecided`/`FollowUpReturnedToRevision` → PIC; `IaCommentAdded` → manager & PIC; `ProgressReported`/`CompletionRequested` → manager; `CompletionDecided` → PIC; `ActionPlanSubmittedToSpi` → admin_spi; `SpiReviewCompleted` (Revisi) → manager; `RevisionForwarded` → PIC; temuan `MENUNGGU_STATUS_EKSTERNAL` → kepala_spi; `ExternalStatusRecorded`/revisi eksternal → manager; `FindingClosed` → manager & pihak terkait.
   Tugas yang selesai ditandai `acted_at` saat penerima melakukan aksi relevan (hook pada service terkait).
3. **Pelacakan**: `first_opened_at` diisi sekali saat penerima membuka detail subjek (endpoint `POST /inbox/open` atau middleware pada show endpoint terkait); `acted_at` saat ditindaklanjuti. Tampilkan ketiganya di Inbox dan riwayat.
4. Notifikasi lonceng (database notifications): `GET /notifications`, `GET /notifications/unread-count` (di-cache pendek per user), `POST /notifications/{id}/read`, `POST /notifications/read-all`.
5. **Scheduler harian** `reminders:daily` (jadwal 07:00 di `routes/console.php`) dengan `config/reminders.php` (`before_days = [30,14,7,3,1]`, `escalate_manager_after = 0`, `escalate_kepala_spi_after = 7`, `unopened_after_days = 3`, `unopened_repeat_days = 3`):
   - TL berstatus `DISETUJUI`/`MENUNGGU_PERSETUJUAN_SELESAI` yang `target_date`-nya H-30/14/7/3/1 → notifikasi ke PIC assignee.
   - TL belum `SELESAI` dan lewat `target_date` → eskalasi ke manager_dept (sekali per hari selama terlambat); terlambat > 7 hari → juga ke kepala_spi.
   - Inbox task `OPEN` dan belum dibuka > 3 hari → pengingat ke penerima, diulang tiap 3 hari selama belum dibuka.
   - **Idempotent** lewat `reminder_logs` (unik per subjek+jenis+tanggal): menjalankan dua kali di hari yang sama tidak menggandakan.
6. Dokumentasi menjalankan scheduler di Laragon/Windows (Task Scheduler memanggil `php artisan schedule:run` tiap menit) di `docs/deploy.md`.
7. Test (pakai `Carbon::setTestNow`): tiap event menghasilkan task+notifikasi ke penerima benar, first_opened/acted tercatat, setiap H-x, eskalasi terlambat & >7 hari, unopened reminder + pengulangan, idempotensi, penerima tanpa akses tidak menerima notifikasi.

**Frontend**
8. `NotificationBell` di topbar: badge unread (poll 60 detik via React Query + refetch on focus), dropdown daftar, klik membuka subjek, "tandai semua dibaca".
9. Menu `inbox` — `/inbox` **Inbox Persetujuan**: `DataTable` tugas (judul, jenis, diterima, pertama dibuka, ditindaklanjuti, status) dengan filter; klik membuka subjek dan mencatat first_opened.
10. Tautan dari notifikasi/inbox langsung ke halaman terkait (route helper terpusat `src/lib/links.ts`).

## Acceptance criteria
- Setiap perpindahan tugas menghasilkan inbox task dengan timestamp diterima/dibuka/ditindaklanjuti.
- Scheduler memberi pengingat H-30/14/7/3/1, eskalasi terlambat, dan pengingat belum dibuka, tanpa duplikasi.
- Notifikasi hanya sampai ke user yang berhak melihat subjeknya.

## Larangan
Jangan kirim email. Jangan membuat polling agresif (<30 detik). Jangan memanggil listener secara sinkron berat di request (gunakan queue `sync`/`database` ringan atau batch).
