# R11 — Hardening & Rilis

## Konteks
R0–R10 selesai. Fokus regresi, keamanan, performa, dokumentasi. Jangan menambah fitur.

## Tugas
1. **Test alur penuh** (feature test BE): registrasi temuan → aktifkan → buat AP untuk 2 departemen → kirim → tentukan PIC → susun TL (batch) → ajukan → manager setujui sebagian/tolak sebagian/revisi → IA komentar → progres sampai 100 → setujui penyelesaian → ajukan ke Admin SPI → Review SPI dengan Revisi (Revisi 1) → teruskan ke PIC → TL baru → selesai → Review SPI Sesuai → semua AP Sesuai → Kepala SPI mencatat **BSR** untuk 1 AP (Revisi 2) → selesai → Sesuai → **SSR** → temuan & AP Closed → PIC kehilangan akses.
2. **Matriks visibilitas**: uji lintas 7 peran × endpoint utama (temuan, AP, TL, dokumen, komentar, laporan, export, inbox): PIC A vs PIC B, departemen lain, sebelum AP dikirim, TL belum disetujui (pemantau tidak melihat), setelah Closed. Sertakan kasus departemen IA sebagai auditee (manager_dept/staff_dept IA vs internal_audit/manager_ia).
3. **Test izin menu**: iterasi semua route; pastikan terlindungi `permission:` (kecuali auth/health); matriks hanya-lihat, override per user, cache izin; `manager_ia`/`direksi` tidak bisa menulis.
4. **Test aturan inti**: bobot integer ≤100/=100, tanggal ≤ deadline, progres tidak turun, rumus progres AP & temuan, nomor registrasi unik paralel, "Aktif sampai", penguncian Closed (old/new), scheduler idempotent.
5. **Performa**: `preventLazyLoading` di dev dan perbaiki N+1 (tree, review-bundle, laporan, inbox), index sesuai query nyata (finding_id, action_plan_id, department_id, status, target_date, recipient_id), review TTL cache dan invalidasi (progres, dashboard, izin), code splitting route FE.
6. **Keamanan**: validasi upload (mime asli, ukuran, nama aman), unduh hanya lewat endpoint terotorisasi satu per satu, rate limit, header keamanan, tidak ada endpoint unduh massal (cek otomatis lewat test yang memindai route).
7. **Seeder demo** lengkap (temuan di berbagai status, AP, TL, revisi, notifikasi) + command reset demo.
8. **Dokumentasi**: README (setup Laragon, env, perintah), `docs/api.md`, `docs/deploy.md` (queue, scheduler `schedule:run` via Task Scheduler Windows, storage, cache, optimize, backup), perbarui `docs/roadmap-remodel.md` bila ada penyimpangan keputusan.
9. Bersihkan kode mati dan komponen duplikat; pastikan tidak ada sisa referensi ke istilah/model lama.

## Acceptance criteria
- Semua test lolos termasuk alur penuh dengan revisi dan SSR.
- Tidak ada N+1 pada halaman utama.
- Orang baru bisa menjalankan proyek dari nol memakai README.

## Larangan
Jangan menambah fitur. Jangan menurunkan aturan visibilitas, penguncian Closed, atau validasi bobot/tanggal demi performa.
