# M1 — Auth, RBAC & Izin Menu Dinamis

## Konteks
M0 selesai. Role: admin_spi, manager_ia, manager_dept, staff_dept, manager_spi (+ superadmin teknis). 1 user = 1 role = 1 departemen. Login biasa (email/username + password).

## Tugas
### Backend — Menu & izin
1. Migration `users`: `name`, `email`, `username` (unik), `password`, `role` (enum — gunakan `App\Enums\Role`), `department_id` (nullable sementara), `is_active`.
2. Migration `departments` (minimal, tanpa FK dulu — FK lengkap M2): `id`, `name`, `code`, `is_active`, timestamp. Dibutuhkan agar kolom `department_id` di `users` valid dan seeder role–departemen berfungsi.
3. Migration `menus`: `id`, `code` (unik, tetap di kode), `name`, `path`, `icon`, `parent_id` (nullable, untuk grup), `sort_order`, `is_active`.
4. Migration `role_menu_permissions`: `role`, `menu_id`, `can_view`, `can_create`, `can_update`, `can_delete` (unik role+menu).
5. Migration `user_menu_permissions`: `user_id`, `menu_id`, `can_view`/`can_create`/`can_update`/`can_delete` nullable (null = ikut role; non-null = override), unik user+menu.
6. `App\Enums\Role` (PHP Enum) dengan 5 role + superadmin, label Indonesia, helper `isManager()`, `isAdminSpi()`, dst.
7. Auth dengan Laravel Sanctum (SPA cookie, paling sederhana untuk Vite dev): `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, `POST /auth/change-password`. Rate limit login (Laravel throttle, 5×/menit/IP+email). User nonaktif tidak bisa login.
8. `PermissionService::effective(User)` → peta `menu_code → {view, create, update, delete}` (override user ?? role). Cache lewat `CacheService` per user.
9. Middleware `permission:{menu_code},{aksi}` (aksi: view|create|update|delete). Rule: GET = view, POST = create, PUT/PATCH = update, DELETE = delete. `can_create/update/delete` hanya efektif bila `can_view` true. Superadmin selalu penuh & tak terbatas.
10. Gate/helper global `can_menu($menu, $action)`. `Gate::before` hanya untuk superadmin; tidak boleh memberi akses bebas.
11. `MenuSeeder` (idempotent via `firstOrCreate`): daftarkan menu awal — `dashboard`, `master.departments`, `master.employees`, `access.permissions`, `audit_trail`, placeholder fitur `findings.reports`, `findings.distribution`, `findings.list`, `action_plans`, `action_plan_reviews`, `evidence`, `assessments`, `verifications`, `exports`. Setelah insert menu, seed default permission per role (sesuai tugas di roadmap §1).
12. Seeder user development per role (password dari env), termasuk superadmin. `is_active = true`.
13. `GET /auth/me` → user, role, departemen, pohon menu yang boleh dilihat (`can_view` true) + izin efektif tiap menu.
14. Invalidasi cache `CacheService` saat izin role/user berubah atau role user berubah.

### Backend — Test (Pest/PHPUnit feature)
15. Login sukses, login gagal (password salah), user nonaktif ditolak.
16. Izin efektif: role saja, override user menambah akses, override user mencabut akses.
17. `create` tanpa `view` → tidak efektif (request create kembalikan 403).
18. Route ditolak 403 tanpa izin; 401 tanpa token.
19. Cache terinvalidasi saat izin berubah.

### Frontend
20. Halaman Login, `AuthProvider`, hook `useAuth`, `ProtectedRoute`, reusable `<RoleGate roles={[...]}>`.
21. Sidebar dibangun dari respons `GET /auth/me` — **bukan** hard-code. Tiri / collapse berdasarkan `parent_id`.
22. Hook `usePermission(menuCode)` → `{canView, canCreate, canUpdate, canDelete}`.
23. Reusable `<Can menu="..." action="create">` dan `<PermissionRoute menu="...">`.
24. Update `DataTable`/`PageHeader` (dari M0) agar tombol Tambah/Ubah/Hapus otomatis disembunyikan berdasarkan izin halaman (prop `permissionMenu`).
25. Halaman 403 dan 404; auto-logout saat 401.

## Acceptance criteria
- Memberi user X izin hanya `can_view` pada satu halaman: user X melihat halaman itu tanpa tombol tambah/ubah/hapus, dan API create/update/delete mengembalikan 403.
- Menu di sidebar hilang jika `can_view` false.
- Override user mengalahkan default role di kedua arah (menambah dan mencabut).
- `/auth/me` mengembalikan role, departemen, menu + izin efektif.
- Test BE lolos (`php artisan test` semua hijau).

## Larangan
- Jangan hard-code menu di FE (wajib dari API).
- Jangan buat UI pengaturan izin (itu M2).
- Jangan biarkan izin menu menembus scope visibilitas/alur kerja (PIC tetap hanya lihat temuannya).
- Jangan beri `Gate::before` akses bebas selain superadmin.
- Jangan menambah role/fitur di luar M1.

## Konvensi kode
- `docs/roadmap.md` selalu baku; ikuti selama proses.
- Backend: Route → FormRequest → Controller tipis → Service → Model → API Resource. Otorisasi Policy.
- Semua migration punya foreign key, index, soft delete bila entitas bisnis (menus/users permissions boleh tanpa soft delete — master lookup saja).
- Cache pakai `App\Support\CacheService` (versi key + invalidasi eksplisit; jangan `Cache::remember` liar).
- FE: komponen reusable di `src/components/ui` + `src/components/shared`; data fetching lewat hook di `src/hooks` pakai TanStack Query.
- Bahasa UI: Indonesia. Kode/variabel: Inggris.
