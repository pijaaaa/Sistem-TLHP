# M4 — Distribusi Temuan & Scoping Visibilitas

## Konteks
M0–M3 selesai. Manager IA mendistribusikan temuan ke satu atau lebih departemen (boleh departemen IA sendiri; manager dept yang menerima = manager departemen tsb). Manager Dept lalu meng-assign ke satu atau lebih PIC (staff) di departemennya. PIC tidak boleh melihat temuan yang di-assign ke PIC lain, walau satu departemen.

## Tugas
**Backend**
1. Tabel `finding_departments`: id, finding_id, round, department_id, status (`DITERIMA`, `PIC_DITUGASKAN`, `DALAM_PROSES`, `SELESAI_100`, `DITERUSKAN_KE_IA`), progress (decimal), forwarded_at.
2. Tabel `finding_assignees`: id, finding_department_id, employee_id/user_id (PIC), assigned_by.
3. API Manager IA: `POST /findings/{id}/distribute` dengan daftar `department_ids` (>=1). Transisi DIKIRIM_KE_IA → DIDISTRIBUSIKAN. Manager IA dapat menambah departemen selama ronde berjalan.
4. API Manager Dept: `POST /finding-departments/{id}/assign` dengan `user_ids` (>=1, harus staff aktif dari departemen yang sama). Dapat menambah/mencabut PIC selama tidak ada evidence yang sudah disetujui dari PIC tsb (jelaskan aturan di ringkasan). Status temuan menjadi DALAM_PROSES saat PIC pertama ditugaskan.
5. **Visibility scope terpusat** (`FindingVisibility` / global scope + policy):
   - admin_spi: semua; manager_ia: semua; manager_spi: temuan tahap MENUNGGU_VERIFIKASI_SPI ke atas + riwayat;
   - manager_dept: hanya temuan yang di-assign ke departemennya;
   - staff_dept: hanya temuan yang di-assign ke dirinya.
   Semua query daftar/detail/dokumen/tindak lanjut wajib lewat scope ini.
6. Cache daftar ringan per user dengan TTL pendek, invalidasi saat distribusi/assign.
7. Test keras: PIC A tidak bisa melihat (list, detail, dokumen, 404/403) temuan milik PIC B satu departemen; manager departemen lain tidak bisa melihat; manager IA dapat assign ke IA sendiri.

**Frontend**
8. Halaman Manager IA: pilih temuan → `DepartmentMultiSelect` (reusable) → distribusi.
9. Halaman Manager Dept: daftar temuan departemen, pilih PIC dengan `EmployeeMultiSelect` (hanya staff departemennya).
10. Halaman PIC: daftar temuan miliknya saja. Gunakan satu komponen `FindingList` dengan prop kolom/aksi per role.

## Acceptance criteria
- Satu temuan bisa ke banyak departemen, satu departemen bisa banyak PIC.
- Test visibilitas PIC lolos untuk semua endpoint.
- Tidak ada filter visibilitas ad-hoc di controller.

## Larangan
Jangan buat tindak lanjut (M5). Jangan kendurkan scope demi kemudahan. Jangan biarkan manager dept memilih staff departemen lain.
